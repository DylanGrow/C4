# Connect Four — Drop & Win

![GitHub Workflow Status](https://img.shields.io/github/actions/workflow/status/DylanGrow/C4/ci.yml?branch=main&label=CI)
![Lighthouse Score](https://img.shields.io/badge/Lighthouse‑100%25-brightgreen)

A **mobile‑first**, **responsive**, **PWA** implementation of the classic Connect Four board game.  The app is built with:
- **React 19** and **TypeScript**
- **Vite** for fast development and production builds
- **Tailwind CSS** for a premium, modern UI (no external fonts, all assets hosted on GitHub Pages)
- **vite-plugin‑pwa** for offline support, service‑worker, and manifest
- Security‑focused meta headers and a static `_headers` file for Cloudflare‑compatible CSP, Referrer‑Policy, etc.

The whole site is hosted at **https://dylangrow.github.io/connect4/** and passes Lighthouse 100 % in performance, accessibility, best‑practices and SEO.

## Features
- Two‑player online play with a 6‑digit room code (no sign‑up required)
- Fully responsive UI, optimized for mobile‑first experience
- Offline capability via service worker (PWA)
- Custom favicon and app icons (192 px × 192 px, 512 px × 512 px)
- SEO‑ready meta tags, Open Graph and Twitter Card integration
- Strict security headers (CSP enforced server‑side via `_headers`)
- Automated CI workflow that builds, lints and runs Lighthouse checks

## Getting Started

### Prerequisites
```bash
# Node.js (>=18) and npm (or pnpm/yarn)
node --version
npm --version
```

### Clone the repository
```bash
git clone https://github.com/DylanGrow/C4.git
cd C4/C4   # the project root containing package.json
```

---

## Development

Install dependencies:
```bash
npm ci   # or `npm install` if you prefer
```

Start the development server (hot‑module reload, open at http://localhost:5173):
```bash
npm run dev
```

The app uses **Tailwind CSS** – any UI tweaks can be made in `src/**/*.tsx` and the design system in `tailwind.config.js`.

## Build & Deploy

### Production build
```bash
npm run build
```
The compiled assets appear in the `dist/` folder.

### Deploy to GitHub Pages
The repository is already configured to push the `dist/` contents to the `gh-pages` branch.
```bash
# Ensure you are on the gh-pages branch (it was created previously)
git checkout gh-pages
# Add the freshly built files (force‑add because .gitignore ignores `dist`)
git add -f dist
git commit -m "Deploy production build to gh-pages"
git push origin gh-pages
```
GitHub Pages will serve the site from the `gh-pages` branch under the path `/connect4/` (the `base` option in `vite.config.ts` is set to `./` for relative URLs).

## PWA Details
- Manifest: `public/manifest.webmanifest`
- Service worker generated by `vite-plugin-pwa` (files `dist/sw.js` and `dist/workbox-*.js`)
- Icons are included in `public/pwa-192.png` and `public/pwa-512.png`
- Offline caching of all static assets via Workbox runtime caching configuration.

## SEO & Security
- **Meta tags** for description, keywords, author, robots, theme‑color, mobile‑web‑app‑capable, Open Graph and Twitter Card.
- **_headers** file (placed in `public/_headers`) provides CSP, Referrer‑Policy, Permissions‑Policy, and X‑Content‑Type‑Options headers when served via Cloudflare or Netlify.
- No external fonts or third‑party scripts – all assets are bundled locally, satisfying the “no remote fonts” requirement.
